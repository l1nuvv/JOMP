# Challenge a design proposal against project evidence

- Start with the specific decision and its candidate options. Read the [active roadmap](../../../docs/ROADMAP.md), then the relevant GDD or task card, source and existing measurements. Resolve factual questions from those sources first. When the decision changes how gameplay states fit together, use [domain-modeling](../domain-modeling/SKILL.md).
- Ask one focused question at a time when the answer depends on owner preference. Present the trade-off and a recommendation grounded in the project. When the owner is away, follow the decision authority in [AGENTS.md](../../../AGENTS.md) and use an available focused check to resolve uncertainty about behavior.
- For the reception hub after MAIN-012, compare return to reception with drop-off at the work site. Use the measured route, available drop-off points and full-bundle cases from the [production plan](../../../docs/development/JOMP_DEVELOPMENT_ROADMAP.md#hub--приёмная-магазин-и-коллекция-плакатов).
- Put the resolved choice, its rationale and the remaining verification in the existing task card or design section.
