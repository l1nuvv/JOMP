# Courtyard art source — 2026-10-28

The models are authored in installed Blender, without paid generators. `Card.blend`, `Scraper.blend` and `Steamer.blend` are editable source files; `build_tools.py` regenerates them and the FBX exports. The Y-up correction composes with the imported FBX root rotation (important for the single-mesh card). Mesh normals are recalculated outward before export. `build_card_face.py` authors the card's neutral yard-number print, without bank branding or details.

`compose_notices.py` contains ten fixed, individually composed document layouts and uses the photographs in Photos/. The default renders Russian; `--language en` uses `notice-en.json` and writes the English variants into Art/Notices/English. It renders installed Windows fonts into PNGs; no font files are included. The distant cat and common headline/image/footer layout were rejected by the owner and replaced. Source/rights records are in docs/ASSET_SOURCES.md.

`expand_notices.py` adds individually authored layouts 11–30 in both languages, retaining the first ten PNGs. New prints export at 512 px width. It validates text bounds and paired dimensions/opacity, writes `notice-catalogue.json` and all-thirty contact sheets `notice-30-ru.jpg` / `notice-30-en.jpg`. Reuse the bundled Python with Pillow; no installation or image-generation credits are required. Original line illustrations are project artwork; design 22 reuses the licensed cat photograph already in Photos/.

`PosterVarietySetup.Apply` is the one-time content migration for FirstShift, already applied. It configures 30 materials per language, verified opaque-sheet flags and physical aspect ratios, then saves the existing scene. Unity needs power-of-two importer resizing for actual BC7 here; separate source proportions prevent stretching. Posters fit inside each stack's original maximum paper size. Runtime uses a local ten-design deep rotation per stack, drawing from the complete catalogue, and retains the two four-strip buffers, deep collision and scrap pool. Do not rerun authoring migrations as routine checks. Current evidence is `Logs/PosterVariety/`; earlier ten-design checks below are historical.

`download_assets.ps1` obtains the eight adopted Poly Haven files and checks MD5 against the API. `download-manifest.json` records exact URLs, hashes and sizes. The three *-info.json files preserve author/dimension metadata.

`StreetArtPass.cs` is the historical art migration and now rejects a live stack scene. `PeelProgressionSetup` configures stack buffers, both languages, the card and bench removal. Do not run PrototypeBuilder/ArtRevision to regenerate this scene. Do not invoke scene-mutating authoring repeatedly as routine verification. The before-scene file here is a recovery copy from the first art pass; it is not a release build or package.

`verify_playmode.cs.txt` and Logs/StreetArt-playmode.txt are historical checks for the superseded two-layer implementation. Do not run that body against the new stack system. Current focused verification is Assets/JustOneMorePeel/Editor/PeelProgressionChecks.cs, run through Unity MCP in fresh Play Mode; Logs/Peel-progression-checks.txt records 65 PASS, 0 FAIL. Eight outline/occlusion checks are in Logs/Peel-selection-checks.txt; five restart/model checks are in Logs/Peel-restart-checks.txt. Tests mutate transient gameplay state, restore preferences and remove their virtual keyboard. Restart or stop afterward.

Both UI languages and printed texture sets are implemented. Broader setting/marketing identity and final pacing remain owner decisions. The bench asset is retained as an unused imported source, but is absent from the scene.
