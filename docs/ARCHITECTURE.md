# Current implementation
Current route experiment: `ThreeAreaPrototype` has 250 courtyard posters, a manually opened door, 104 basement posters and a final hall with 96 across nine stacks. `PeelRoutePrototype` controls gates and route-review mode; `PeelBasementLight` switches basement materials and the lamp without a full-screen overlay. A dim shader approximates daylight at the entrance when the first door is open; it is not shadowed light transport. The former two-area `PeelAreaExperiment` and `FirstShift` remain separate experiments. The chronological descriptions below may refer to earlier scenes.
Latest A03 experiment: `PeelAreaExperiment` listens for `PeelGame.PosterWasCleared`, opens the marked barrier when its three-sheet stack is cleared, supplies the current-area count and localizes the sign and reveal. The second area and passage are temporary scene blockout. The original courtyard shell's combined metal mesh has been rebuilt without the old full-width back boundary; new boundary colliders form the opening. Restart reloads this state; there is no world persistence. See ROADMAP and PLAYTEST for test scope.
Latest poster audit: [POSTER_SYSTEM_AUDIT](POSTER_SYSTEM_AUDIT.md). PeelPosterStack retains geometry/index/material caches; `deepCount` is the live range within capacity. A layer advance builds the complete collision mesh and uploads the clipped display mesh once. `Poster.BuildDeepLayers`, `Poster.Visibility` and `Poster.Deform` are profiler markers. PeelStrip updates held flutter in LateUpdate only when Pull has not already deformed that frame, preserving synchronous Pull results. Visibility Initialize resets its previous index; render flags are assigned on visibility transitions. The diagnostic PosterPerformanceProbe is UNITY_EDITOR-only, opt-in, and must run in a disposable Play session; it is never attached to the saved scene.

PeelWallVisibility caches conservative bounds and renderers for stationary poster patches, handles 60 m/frustum render culling without touching logical or collision state, and maintains a 2 m spatial grid for steam neighbour lookup. Off-camera patches skip deep-occlusion camera updates. The PC URP asset enables SRP Batcher, InstancedDrawing and GPU occlusion culling; PERFORMANCE records measured results and method scope.
Unity 6000.6.0f1, URP, Input System, Cinemachine and imported Unity Starter Assets. Preserve the current package baseline.

## Runtime components
- PeelGame: explicit Intro/Playing/Paused/Shop/Settings screen states with a settings return state, cached Starter Assets controller/input references, grip rules, progression, purchases and prototype IMGUI presentation. No reflection is used for runtime Starter Assets integration.
- PeelSettings: EN/RU UI table, paired notice material sets, wall-text translation, sound/sensitivity preferences and change notification. Settings apply immediately; PlayerPrefs stores preferences only.
- PeelPosterStack: 128 logical posters per authored patch, initial front/back notice designs and a deterministic older-design sequence. Two four-strip buffers are reused; logical depth is integer state. A combined mesh contains all deeper sheets from startup; its non-convex MeshCollider blocks targeting through visible lower paper. The collider is rebound when the mesh changes and disabled when empty.
- PeelStrip: reusable deformable geometry, cached renderer/collider, idempotent removal within the current poster. An underlying buffer cannot become exposed through a missing front strip.
- PeelScrapPool: 32 preallocated meshes/objects with no colliders. Starter tearing emits strips; an intact scraper/steam poster emits one full-sheet visual. A partly torn poster retains its missing parts.
- PeelPosterOutline: one closed LineRenderer around the whole reachable top poster under the ray. Occluded/out-of-range targets and menus clear selection.
- PeelToolView: three Blender-authored prefab views (card, scraper, steam), selected by upgrade/tool state. Shared imported meshes/materials; steam particles at the nozzle.
- PeelWorkbench: marker on the imported tool-cart collider.
- StarterAssets.FirstPersonController / StarterAssetsInputs: existing movement, look, cursor and focus integration.
## Invariants
One grip captures one strip with the card, a whole front poster with the scraper, or up to three visible nearby front posters with steam (up to five after the experimental wider-steam purchase). Holding LMB may start another grip after a fresh reach/occlusion raycast. Release is still required after a menu transition or tool switch.
Paper payout is $2 per removed part; a complete fresh poster pays $8. Partly paid posters only pay for remaining parts.
Advance a stack only after every front part is detached and after the active grip references are cleared. New layers reuse display buffers and synchronize physics once after advancement.
Cursor ownership is synchronized with StarterAssetsInputs. Menus keep the cursor free; gameplay locks it; active peeling holds the camera steady until release.
Runtime paper searches occur at startup. Steam searches the cached 19 stacks, not the scene. Materials refresh on language changes or buffer reuse.
## Authoring and verification
PeelProgressionSetup configures the existing scene's stack buffers, paired languages and starter card, then removes the decorative bench. It is a deliberate migration, not a routine check.
PrototypeBuilder, ArtRevision and StreetArtPass are historical helpers. StreetArtPass rejects a live poster-stack scene; do not use them to regenerate it. Preserve GUIDs and the original combined-shell/collider split.
PeelProgressionChecks is an Editor/MCP runtime check, not player-facing functionality. It uses a temporary virtual Input System keyboard and restores settings/removes the device afterward. The older SourceArt/StreetRevision/verify_playmode.cs.txt checks the superseded two-layer implementation and must not be run against the new stack system.
